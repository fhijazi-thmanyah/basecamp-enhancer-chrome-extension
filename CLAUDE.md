# CLAUDE.md — basecamp-enhancer

MV3 Chrome extension scoped to Basecamp. Three features, all idempotent, continuous, and individually toggleable. See @README.md for install/usage.

## Architecture

Content script (`content.js`, one IIFE) + toolbar popup (`popup.html`/`popup.js`). No build step, no dependencies.

**Settings flow (narrow waist = `chrome.storage.sync`):** popup is dumb — it reads/writes the three feature booleans (`timeLabels`, `rtl`, `inlineReactions`) plus the `reactionEmojis` array. The content script holds the live `settings` object, seeds it from storage on load, and listens on `chrome.storage.onChanged` to apply/revert **without a reload**. `reconcile()` is the single function that makes the page match settings (`decorateAllTimes`/`removeTimeLabels`, `applyAutoDir`/`removeAutoDir`, `applyInlineReactions`/`removeReactionBars`). All off ⇒ fully reverted ⇒ plain Basecamp. Adding a feature = add its key to `DEFAULTS` (both files), a toggle row in `popup.html`, and an apply+remove pair wired into `reconcile()`/`enhance()`.

- **`decorateTime` / `decorateAllTimes`** — append a `.bce-ago` span with `Intl.RelativeTimeFormat` output (`numeric: "always"` → "N units ago", never the word "yesterday"). Idempotent: reuses the existing `:scope > .bce-ago` child instead of appending a new one. Two skip rules: (1) the whole ±1-calendar-day range (`calendarDayDiff`) — Basecamp shows yesterday/today/tomorrow as a relative *word*, so a badge is redundant; (2) any `<time>` with a later sibling `<time>` (`hasLaterTimeSibling`). Basecamp emits **two** `<time>` per timestamp sharing one `datetime` (`<a>` wraps `<time data-local="weekday">Tuesday</time>` + `<time data-local="time-or-date">Jun 2</time>`); rule 2 badges only the **last** sibling so the label never appears twice (`Tuesday` stays plain, `Jun 2 (6 days ago)` gets the badge). `decorateAllTimes` handles both descendant `<time>` (via `querySelectorAll`) **and** a root node that *is* a `<time>` (the observer hands these directly — `querySelectorAll` would miss them).
- **`applyAutoDir` / `setAutoDir`** — sets `dir="auto"` on `RTL_SELECTORS` (rendered content **and** editable fields: `textarea`, `input[type=text|search]`, `[contenteditable]`, `trix-editor`) so typed Arabic auto-directions live. `setAutoDir` only sets when the element has **no** `dir` already, and tags it `data-bce-dir` — so `removeAutoDir` reverts exactly what we touched and never disturbs Basecamp's own `dir` attributes.
- **Inline reactions (`applyInlineReactions`/`injectReactionBar`/`sendBoost`)** — Basecamp calls reactions **boosts**. Every reactable item (card, comment, message, chat line, ping) renders a uniform `.boosts` container holding a `.boosts__new-boost` "+" link whose href is `/<acct>/buckets/<bucket>/boosts/new?boost[boostable_gid]=<base64 gid>`. That single anchor is the narrow waist: `boostTarget()` derives the create endpoint (same path minus `/new`) and base64-decodes the gid from it. `injectReactionBar` appends a `.bce-reactions` span of `<button.bce-react-btn>` (one per `settings.reactionEmojis`) into each `.boosts`, tagged with a `data-sig` of the emoji set so it rebuilds only when the set changes. (Do **not** re-add a `.hidden-on-template` skip: that class sits on *every* chat line's boosts wrapper, not just Basecamp's clone template — skipping it silently kills all chat/ping reactions. Cloned bars are harmless anyway since clicks use delegation.) Clicks go through **one delegated, capturing** document listener (survives Basecamp cloning; intercepts before Basecamp). `sendBoost` POSTs `authenticity_token` (from `meta[name=csrf-token]`) + `boost[boostable_gid]` + `boost[content]=<emoji>` with `Accept: text/vnd.turbo-stream.html, text/html`; `applyBoostResponse` swaps in the returned `<turbo-frame id="boosts_recording_…">` (or renders turbo-stream) so the reaction shows without reload, leaving the sibling `.bce-reactions` bar untouched.
- **Recently-used rotation (MRU)** — `reactionEmojis` doubles as the bar *and* the MRU cache (cap `MRU_MAX=8`). `recordEmojiUse(emoji)` promotes an emoji to the front (dedup, trim) and persists → `onChanged` rebuilds every bar in newest-first order. Fed from two places: `sendBoost` (our bar) and `captureRecentBoosts` (the observer), which reads `boostEmoji()` (leading `\p{Extended_Pictographic}` grapheme) off any `.boost[data-creator-id=<me>]` — so reactions made through Basecamp's **native** picker also train the bar. `<me>` = `meta[name=current-person-id]`. Capture is gated by `captureReadyAt` (re-armed 2 s after every `turbo:load`) so a page's *existing* boosts and page-to-page navs don't flood the MRU with history. The popup's emoji editor seeds/edits the same list, parsing input via `Intl.Segmenter` (grapheme) so packed/spaced/ZWJ emoji all split correctly.
- **`enhance(root)`** — runs the **enabled** features on a subtree; bails early if `root` is one of our own `.bce-ago` badges to avoid observer-feedback rework (re-enhancing a `.bce-reactions` bar is a harmless no-op).
- **Wiring** — `run_at: document_start`, immediate `enhance()` (uses `DEFAULTS` until storage resolves, then `reconcile()` corrects), a `MutationObserver` on `document.documentElement` (continuous), **`turbo:load`/`turbo:render`/`turbo:frame-render`/`turbo:before-stream-render` listeners that rAF-coalesce a `reconcile()`** (see flicker gotcha), `DOMContentLoaded`/`load` full sweeps, and a 60 s interval (guarded by `settings.timeLabels`) to refresh relative labels.

## Gotchas / invariants

- **Idempotency is load-bearing** — the observer fires on our own badge insertions; the early-return + reuse-existing-badge logic is what prevents loops/duplicates. Don't break it.
- **`<time>` root case** — when adding `<time>` handling, remember `querySelectorAll("time")` matches descendants only. Bare-node decoration is a separate explicit check.
- **Revert must be exact** — RTL revert only removes `dir` from `[data-bce-dir]`-tagged nodes; never blanket-strip `dir`, or you'd wipe Basecamp's own attributes. Keep `setAutoDir`'s "only when no existing `dir`" + tag invariant.
- To support a new Basecamp view's RTL, add its content class to `RTL_SELECTORS`.
- **Flicker fix (was: time labels "appear and reappear")** — Basecamp streams updates over a `turbo-cable-stream-source` (WebSocket). A stream/morph render strips our badge/bar from *inside* an element that stays in place; the `MutationObserver` only fires on **added** nodes, so it never re-adds them — they'd vanish until the 60 s interval. The `turbo:*` listeners (which rAF-coalesce a `reconcile()`) are what restore them on the next frame. Don't remove them; the observer alone is insufficient.
- **Reactions post via the boost gid, not the DOM** — `sendBoost` derives everything (endpoint + gid) from the `.boosts__new-boost` href; it does **not** click Basecamp's UI. The CSRF token comes from `meta[name=csrf-token]` (works for all forms — no need to GET `/boosts/new`). If Basecamp changes the boost URL shape or gid encoding, update `boostTarget()` only.

## Packaging / publishing

- Icons: `icon.png` (512², source of truth) = the Basecamp logo-mark with the orange Basecamp app-icon composited as a rounded badge (soft shadow) in the bottom-right. Downscale to the four sizes with `for s in 16 32 48 128; do magick icon.png -filter Lanczos -resize ${s}x${s} -strip icons/icon$s.png; done`. Re-run after editing `icon.png`.
- Build the Web Store upload zip (runtime files only, manifest at root): `zip -r basecamp-enhancer.zip manifest.json content.js popup.html popup.js styles.css icons/ -x '*.DS_Store'`. Excludes `README.md`/`CLAUDE.md`/`icon.png`/docs.
- Bump `version` in `manifest.json` for every Web Store re-upload (it rejects duplicate versions). Distribution: Chrome Web Store, **Unlisted**.

## Testing

The **thmanyah** Chrome profile (`chrome-profiles.json` → deviceId `d78ac67f…`) is signed into Basecamp — use it via `/chrome` for live testing. Reactions were verified end-to-end on a real card (`.../cards/10063474912`) and ping (`.../circles/46769252`): bars inject into every `.boosts`, a delegated click POSTs a boost (200) and renders it inline, then the test boost is DELETEd (`DELETE /<acct>/buckets/<bucket>/boosts/<id>` with `X-CSRF-Token`) to leave no trace — **always clean up test boosts**, they notify subscribers. Time-label/RTL logic is also verifiable by injecting `content.js` against synthetic markup (single badge after double-run, correct relative text, `dir=auto` → rtl/ltr). The `javascript_tool` REPL mangles top-level `await` — stash results on a `window.__x` global in one call and read them back in the next.

Reloading the unpacked extension to pick up edits requires `chrome://extensions` (the Chrome MCP can't script `chrome://`) — ask Faris to hit **reload**, or inject a page-context replica to verify logic live.
